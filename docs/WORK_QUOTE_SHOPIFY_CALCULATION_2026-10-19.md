non-Owners or missing effective scopes stop before calculation. SDK bootstrap

## Exact pricing and held results

- At most 20 unique native variants, quantities 1–999, bounded integer cents,
  copied input and stable input/address fingerprints reuse `agreementHash`.
- Shopify receives explicit USD price overrides for reviewed quoted prices,
  exact personalization attributes, shipping price/title and the supplied
  address. It never falls back to a customer's changing default address.
- Decimal responses are parsed exactly into integer cents. Shop and presentment
  currencies must both be USD and agree; line amounts, quantities and options
  must match. Shipping/discount and the complete total equation must reconcile.
- Automatic discounts and checkout discount additions are explicitly false.
  A supplied reservation/code must read back exactly, with its original v13 or
  approved universal policy and exact expected discount. No points are deducted,
  code issued or reservation changed here. No public Rewards/native-checkout
  acceptance is implied by these input guards.
- Missing address returns `address_required`, `calculation: null`,
  `publishable: false` and a provisional preview. A Shopify-reported zero tax
  without an address is NOT final verified tax. `freezeWorkQuote` rejects the
  absent calculation. No address, shipping rule or tax policy is invented.
- Warnings, skipped/extra discounts, inclusive-tax results, transformations that
  alter the requested lines/prices, user errors, mixed currencies and read
  outages hold the result. Tax-inclusive agreement semantics and separate custom
  material/labor fee lines are not implemented in the current native-variant
  agreement model; callers must not drop these fees to force conversion.
- A complete calculation produces the existing `freezeWorkQuote` calculation
  shape. Its exact input hash and address hash bind the supplied server intent.
  Version-2 agreement terms now also persist the exact normalized private
  address and shipping label for the customer-owned projection. These
  fingerprints do not independently prove the real-world address; consuming
  public routes and customer presentation are still unfinished.
- Each SDK request is bounded and uses `tries: 1`. No automatic external retry,
  create, order completion or manual paid state is introduced. The existing
  one-create claim and ambiguous-create reconciliation remain unchanged.
